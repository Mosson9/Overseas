# 10 · 合规与法律（实操手册）

> 脑图几乎缺失的大风险敞口。本篇给你**各国数据法、数据本地化、实体税务架构、内容/广告合规**的落地清单。合规不是成本，是你能持续运营的前提。

---

## 一、最佳实践

### 1.1 合规前置，不要事后补 ✅
- GDPR 罚款最高营收 4%；数据/未成年人/支付合规缺失是下架与罚款主因。上线前就内置。

### 1.2 一案一议，不照搬模板 ✅
- 跨境实体、税务、资金架构因主体/区域/业务差异极大，必须由专业顾问定制。

---

## 二、数据隐私法规（按区域落地）

| 法规 | 地区 | 要点 | 你要做的 |
|---|---|---|---|
| GDPR | 欧盟 | 同意、可删除、可携、DPO | 同意弹窗、删除入口、隐私政策、数据处理协议 |
| CCPA/CPRA | 美国加州 | 消费者数据权 | Do-Not-Sell、删除请求通道 |
| DPDP Act | 印度 | 数据保护+本地化倾向 | 印度用户数据合规存储 |
| PDPL | 沙特/UAE | MENA 数据保护+部分本地化 | 海湾数据合规、必要时本地节点 |
| PDPA | 新/泰/马 | 东南亚数据保护 | 同意与告知 |
| COPPA | 美国 | 儿童(<13)隐私 | 年龄门、禁止收集儿童数据 |

🔧 **通用动作**：多语言隐私政策与用户协议、App 内同意弹窗、数据删除/导出入口、未成年人年龄门、**SDK 数据采集合规审计**（很多三方 SDK 违规采集是处罚点）、iOS ATT 合规。

## 三、数据本地化与基础设施
- 印度、印尼、沙特、俄罗斯等对**用户数据存储位置**有要求。
- 选云/CDN 时考虑**本地节点/区域合规**（见 11 技术篇）。

---

## 四、实体、税务与架构

### 4.1 典型架构
```
开曼/BVI（顶层控股）
   └─ 香港/新加坡（运营+收单主体）
         └─ 各地子公司/分支（本地运营/合规）
```

### 4.2 税务
- **VAT/GST**：欧盟、海湾、东南亚对数字服务普遍要求代征代缴。
- **MoR 渠道（Paddle/Xsolla）可把税务外包**，省去自行在多国注册税号。
- **转让定价**：境内外关联交易需符合公允价格，留存文档。

### 4.3 主体一致性
- App 主体、收款主体、付款卡一致（与 03 账号篇呼应），合规与风控双重需要。

## 五、内容与广告合规
- 博彩玩法、金融诱导、夸大交友承诺的广告——分国家审查（与 05 买量、08 变现篇呼应）。
- 中东宗教/政治/两性法律红线（与 07 审核篇呼应）。
- 用户协议含**禁止令人反感内容的 0 容忍条款**（Apple/Google UGC 硬要求）。

## 六、常见的坑 + 解决方案

| 坑 | 后果 | 解决方案 |
|---|---|---|
| 无隐私政策/同意机制 | 拒审+罚款 | 多语言隐私政策+同意弹窗 |
| SDK 违规采集数据 | 罚款+下架 | SDK 合规审计、最小必要采集 |
| 忽视数据本地化 | 当地违规 | 本地节点/区域合规存储 |
| 无实体税务架构 | 欠税补税罚款 | 离岸+本地架构、MoR 外包税务 |
| 未成年人无防护 | 重罚下架 | 年龄门+COPPA 合规 |
| 博彩/广告越界 | 法律+下架 | 分国家合规审查 |
| 照搬别人架构 | 踩自身业务的坑 | 专业顾问一案一议 |
